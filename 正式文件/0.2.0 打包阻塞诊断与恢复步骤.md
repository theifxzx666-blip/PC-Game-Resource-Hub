## 三、根因

### 根因 1：本机无法创建「目录符号链接」（核心）

实测（`日志\link-test.log`、`日志\link-test2.log`）：

| 操作 | ASCII 路径 | 中文路径 |
| --- | --- | --- |
| `fs.symlinkSync(target, link, 'dir')` | **ERR ENOENT** | **ERR ENOENT** |
| `fs.symlinkSync(target, link, 'junction')` | OK | OK |
| `fs.symlinkSync(target, link, 'file')` | OK | OK |

即：**目录符号链接一律失败，与中文路径无关**；junction 与文件符号链接正常。

而 pnpm 默认的 `isolated` 布局（虚拟 store `.pnpm`）大量依赖**目录符号链接**，因此在 `Failed to create symlink ... os error 2` 上卡死，`node_modules` 只能装到一半。

**处置**：改用扁平布局，绕开目录符号链接。已写入配置（见第四节）。

### 根因 2：WorkBuddy 沙箱把项目路径视为「工作区外路径」

- `CODEBUDDY_SAFE_DELETE_ENABLED=1`、`CODEBUDDY_SAFE_DELETE_SANDBOX=1`、`GENIE_TRASH_DIR` 等启用了一套安全删除 / 沙箱层（相关变量快照见 `临时文件\_探查\env-hook.txt`）。
- 该层会**拒绝**对 `F:\Codex\Work\PC游戏资源服务工具\...\node_modules\...` 与 `F:\Codex\Supports\pnpm-store\...` 的读 / 写 / 删，表现为 pnpm 收到 `os error 5`（拒绝访问）。
- 把项目复制进 WorkBuddy 工作区后**仍然被拦**（连 `F:\[AI]Workbuddy\...\构建工作区\客户端源码\node_modules\...` 也在拒绝列表里）。
- 结论：**在 WorkBuddy 工具内无法完成依赖安装**，必须换一个不受该层约束的终端。

### 根因 3：原始 `node_modules` 已被「无声损坏」

因为根因 2，此前某次安装在 store 读取被拒的情况下仍然报成功，导致个别包只落下一两个文件：

- `node_modules\.pnpm\dotenv-expand@11.0.7\node_modules\dotenv-expand\` 只剩一个 `tea.yaml`（其余文件缺失）
- `@peculiar\asn1-schema` 缺 `build\cjs\index.js`

这就是 `Cannot find module 'dotenv-expand'` 的来源。

### 根因 4：pnpm 12 的配置位置与字段名与旧版不同

- pnpm 12 用 `pnpm-workspace.yaml` 的 **`allowBuilds`**，不是 `onlyBuiltDependencies`（依据：pnpm 12.9.1 自带 `CHANGELOG.md`）。
- 该文件里原来是被**交互式安装写入的占位符**，值字面量就是 `set this to true or false`，pnpm 无法解析 → `ERR_PNPM_IGNORED_BUILDS`。
- 另外 `node-linker` 写在 `.npmrc` 里**未生效**，写在 `pnpm-workspace.yaml` 的 `nodeLinker` 才生效（已实测：改后 pnpm 把包直接铺到扁平 `node_modules\`）。

## 七、回退方案

| 改动 | 回退方式 |
| --- | --- |
| `package.json` 依赖版本 `*` | 可改回具体版本；`*` 是为规避 npm 解析 `latest` dist-tag 的网络失败 |
| `package.json` 的 `electron: 44.4.5` | **不要改**，必须与本地缓存 zip 版本一致，否则要重新下载 158 MB |
| `package.json` 的 `esbuild` 依赖 | 保留（`build:preload` 脚本确实依赖它） |
| `package.json` 的 `npmRebuild` / `nodeGypRebuild` | 可删除，但删除后 `node_modules\.bin` 可能再次被 `@electron/rebuild` 破坏 |
| `scripts\verify-deps.cjs` + `verify:deps` 脚本 | 建议保留，能提前发现两类静默损坏 |
| `pnpm-workspace.yaml` / `pnpm-lock.yaml` | 保留但不再使用；确认 npm 链路稳定后可删 |
