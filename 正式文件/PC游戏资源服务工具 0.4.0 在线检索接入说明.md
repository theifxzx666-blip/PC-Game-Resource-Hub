# PC 游戏资源服务工具 · 在线检索接入说明（0.4.0）

> 交付物：`正式文件\游戏资源服务工具演示 0.4.0.exe`
> 适用范围：资源中心「在线检索」功能的数据源配置、契约约定与排障。

---

## 1. 这次解决什么问题

0.3.0 及以前，资源中心的「资源检索」只能读三类本地数据：内置离线目录、缓存文件、以及一个单点配置的 `catalogBaseUrl`。界面能筛能搜，但**没有联网能力**——数据从哪来，取决于你有没有手动往目录文件里塞条目。

0.4.0 把这条链路打通：**可配置多个在线数据源，并发拉取、跨源去重合并、带缓存与逐源状态反馈**。搜索框后面是真联网。

| 能力 | 0.3.0 | 0.4.0 |
|---|---|---|
| 数据来源 | 内置离线 / 本地缓存 / 单一 catalog 地址 | **多源聚合**（JSON 接口 + RSS 订阅，可增删改） |
| 拉取方式 | 全量拉一份目录 | **并发拉取 + 单源独立超时** |
| 去重 | 无 | **跨源去重合并**，多源命中打标 |
| 失败处理 | 整体降级 | **单源失败隔离**，其余源结果不受影响 |
| 筛选 | 关键词 + 类型 + 游戏 | 关键词 + 类型 / 游戏 / 来源 / 状态 / 风险 + 排序 + 分页 |
| 缓存 | 目录级 | **检索结果级**，可配 TTL、可手动清除 |
| 排障 | 只有一条错误提示 | **逐源状态条 + 单源连通性测试** |

## 2. 数据源契约

在「设置 → 在线检索数据源」里新增数据源，二选一。

### 2.1 JSON 接口（`kind = json`）

```
GET {url}
```

响应体（推荐形态）：

```json
{
  "version": "2026-10-06",
  "updatedAt": "2026-10-06 12:00:00",
  "resources": [
    {
      "id": "res-1001",
      "title": "星陨边境 探索辅助工具",
      "kind": "修改器",
      "gameName": "星陨边境",
      "gameAliases": ["星陨", "Starfall Frontier"],
      "version": "1.4.2",
      "compatibleVersion": "星陨边境 1.4.2",
      "gameVersion": "1.4.2",
      "source": "已验证作者页",
      "status": "可用",
      "updatedAt": "2026-09-26",
      "description": "单机模式使用的修改器。",
      "tags": ["单机", "版本匹配"],
      "risk": "中",
      "downloadUrl": "https://example.com/a/starfall-1.4.2.zip",
      "fileName": "starfall-1.4.2.zip",
      "homepage": "https://example.com/a/shared"
    }
  ]
}
```

**宽容解析规则**（对接第三方接口时很关键）：

- 顶层数组也可以直接用裸数组 `[ {...}, {...} ]`，或放在 `items` / `data` 字段下——三种都认。
- 字段名有别名兜底：`title`/`name`/`displayName`、`kind`/`type`、`gameName`/`game`、`downloadUrl`/`download`/`url`、`homepage`/`link`、`updatedAt`/`updated`/`pubDate`/`date`、`description`/`summary`/`desc`、`tags`/`categories`、`risk`/`riskLevel`。
- **缺 `id` 会自动补一个稳定 id**（由标题归一化生成）；**缺 `title` 的条目直接丢弃**。
- `kind` 不在 `修改器 / 存档 / MOD / 补丁` 内的，回落到 `MOD`；`status` 不在 `可用 / 待核实 / 不适配` 内的回落 `待核实`；`risk` 不在 `低 / 中` 内的回落 `低`。
- 顶层既没有 `resources` 也没有 `items` / `data` 数组，会直接报错并回显实际结构片段，方便定位。

### 2.2 RSS / Atom 订阅（`kind = rss`）

```
GET {url}
```

支持 RSS 2.0 的 `<item>` 与 Atom 的 `<entry>`，自动识别。映射规则：

| 来源字段 | 映射到 |
|---|---|
| `title` | `title` |
| `link` / `<link href>` | `homepage` |
| `description` / `summary` / `content` | `description`（截断 500 字，去 HTML 标签，解 CDATA） |
| `pubDate` / `updated` / `published` | `updatedAt` |
| `category` | `tags`（最多 6 个） |

RSS 条目**恒为「待核实」状态、恒无下载地址**——这是刻意的：订阅源无法验证资源可用性，界面必须让用户看到这一点。类型会按标题/描述/分类里的关键词猜（`存档`/`save` → 存档，`补丁`/`汉化`/`patch` → 补丁，`修改器`/`trainer`/`cheat` → 修改器，其余 → MOD）。

### 2.3 请求头

需要鉴权的接口，在「请求头」里按行填写：

```
Authorization: Bearer <token>
X-Api-Version: 2
```

## 3. 去重合并逻辑

同一资源被多个源命中时：

1. **识别键**：优先用 `id`；无 `id` 时用 `标题 + 游戏名` 的归一化文本。
2. **合并**：条目的 `sourceIds` / `sourceNames` 累积，命中 2 个以上源时标 `multiSource = true`，卡片上显示「多源命中」标签。
3. **字段补齐**：优先级数字小的源为高优先级。高优先级源会**补齐**当前条目为空的字段（下载地址、文件名、主页、描述、版本、适配版本、游戏名、更新时间、标签、别名），并在自身状态为「可用」时把状态**提升**为可用。
4. **不覆盖**：低优先级源永远不会覆盖高优先级源已有的非空值。缺下载地址的条目不会因为低优先级源也缺而被清空。

> 实践建议：把**最可信、字段最全**的源设为优先级 1～10，把**订阅类、聚合类**源设为 50 以上。

## 4. 降级链路

检索永远会返回结果，界面不会白屏：

```
① 真实联网（并发拉取全部启用源）
      ↓ 全部源失败 / 无启用源
② 本地检索缓存（TTL 内直接命中，不发请求）
      ↓ 无缓存
③ 内置离线目录（5 条演示数据，标注「离线兜底」）
```

界面顶部「结果来源」标签会明确显示当前处于哪一级：

| 标签 | 含义 |
|---|---|
| **实时联网** | 本次真实拉取成功 |
| **本地缓存** | 命中 TTL 内的缓存，未发请求 |
| **离线兜底** | 全部源失败且无缓存，用内置数据 |

**未配置任何多源**时还有一条兼容路径：若「在线资源目录地址」填了值，会退回旧的单源 `catalog.json` 拉取模式，并在状态条里提示「正在回退使用设置 → 在线资源目录地址」。

## 5. 界面怎么用

### 5.1 配置数据源

1. 左侧导航 → **设置**
2. 滚到 **在线检索数据源** 区块
3. 点 **新增数据源**，填名称、类型、地址；需要鉴权就填请求头
4. 点 **测试连通性** —— 成功会显示条数与样例标题，失败会显示具体原因（HTTP 状态 / 超时 / 非 JSON / 结构不符）
5. 点 **保存设置** 落盘
6. 回到 **资源中心**，点 **联网刷新**

> 数据源配置保存在 `%APPDATA%\PCGameResourceHub\data\config.json` 的 `searchSources` 数组里。

### 5.2 检索与筛选

- **关键词**：命中标题、游戏名、游戏别名、来源、版本、适配版本、游戏版本、描述、标签、命中源名。回车即搜。
- **筛选**：游戏 / 来源 / 状态 / 风险 四个下拉（选项由当前结果集动态生成），加类型分段控件。
- **排序**：相关性（默认）/ 最近更新 / 按标题 / 按来源。
- **只看已入库游戏**：勾上后只保留游戏名或别名能匹配你游戏库里游戏名的条目。
- **分页**：每页 12 / 24 / 48 / 96 可选。

相关性打分权重（用于理解排序结果）：

| 命中位置 | 分值 |
|---|---|
| 标题完全相等 | 120 |
| 标题前缀匹配 | 80 |
| 标题包含 | 60 |
| 游戏名包含 | 40 |
| 游戏别名包含 | 32 |
| 标签包含 | 20 |
| 来源包含 | 12 |
| 描述包含 | 10 |
| 状态「可用」 | +6 |
| 风险「低」 | +3 |
| 有下载地址 | +4 |

### 5.3 结果动作

| 动作 | 说明 |
|---|---|
| **详情** | 弹窗展示全字段，含「命中数据源」列表 |
| **加入我的资源** | 写入本地资源库（`library.json`） |
| **下载** | 投递到下载队列，带进度条；检索结果源不在本地目录里，走的是独立的 `search:enqueueDownload` 通道 |
| **复制链接** | 复制主页地址到剪贴板 |
| **打开主页** | 用系统默认程序打开 |

`downloadUrl` 为空的条目，「下载」按钮为禁用态——这覆盖了所有 RSS 条目。

## 6. 参数调优

| 配置项 | 默认 | 说明 |
|---|---|---|
| 检索缓存有效期 | 30 分钟 | TTL 内重复检索直接命中缓存；点「联网刷新」总是绕过 |
| 单源请求超时 | 8000 ms | 单个源卡死不会拖垮整轮检索 |

两个参数都在「设置」页底部。超时值设太小会导致慢源持续报超时。

## 7. 排障

| 现象 | 原因 | 处置 |
|---|---|---|
| 顶部提示「尚未配置在线数据源」 | `searchSources` 为空 | 设置页新增数据源；或填「在线资源目录地址」走单源模式 |
| 某个源显示黄色告警条 | 该源拉取失败 | 设置页点该源「测试连通性」看具体原因 |
| 测试报「返回结构与契约不符」 | 响应里找不到 `resources` / `items` / `data` 数组 | 核对接口返回；错误消息里会回显实际结构片段 |
| 测试报「响应不是合法 JSON」 | 地址返回了 HTML（常见于登录页 / 404 页） | 核对地址；可能需要请求头鉴权 |
| 测试报「请求超时」 | 源慢或网络不通 | 调大「单源请求超时」；确认网络可达 |
| 检索结果一直是「本地缓存」 | TTL 未过期 | 点「联网刷新」，或在设置页「清除检索缓存」 |
| 结果一直是「离线兜底」 | 全部源失败 | 按上面逐条排查；短期内可用内置离线数据 |
| 资源出现在多个源但只显示一条 | 这是设计行为 | 卡片上的「多源命中」标签与详情里的「命中数据源」可以看出合并了哪几个源 |

## 8. 合规边界（沿用项目红线）

在线检索只做**检索与呈现**，不下载、不解析、不执行任何来源的内容；下载动作走的是独立的、用户显式触发的下载队列。

以下能力**不实现**，未来也不计划实现：反作弊规避提示、Windows Defender 白名单、DRM 绕过、破解分发、联网游戏辅助、账号体系规避。

对状态非「可用」或风险非「低」的条目，界面必须给出显式提示（详情弹窗里的黄色告警），不允许静默呈现为「正常可用」。

自动化测试脚本（纯 Node，不需要启动 Electron）：

```bash
cd "临时文件/_探查"
bash _run_onlineSearch_test.sh
```

覆盖 48 项断言：多源聚合、跨源去重合并、字段补齐、RSS 解析与类型猜测、关键词与五维筛选、相关性排序、分页、单源失败隔离、单源超时隔离、测试连通性的四类错误、缓存命中与强制刷新、离线降级、单目录兼容回退、禁用源跳过。

实现方式：起本地 mock HTTP 服务器扮演多源，用 ESM loader hook 把 `electron` 导入重定向到测试桩，再用临时沙箱接管 `%APPDATA%`，全程不触碰真实用户数据。
